# 灵感库的文件形态与编号规则

Status: accepted（决定于 [#8](https://github.com/JoeWest9966/md/issues/8)）。**「布局」与「身份与编排」被 [#13](https://github.com/JoeWest9966/md/issues/13) 修订（2026-10-16）**：门槛卡搬出稿件 front matter，稿件文件变纯正文。被改的原句一律保留 + 就地加注，读到「（被 #13 改）」就是它。

100 条灵感要住进一个仓库：多个 agent 会话并发地写、读者按批遇见它们、最后导出成 EPUB/PDF。三条约束决定形态：**写的人并行、读的人串行**（真闸门在**审读**那一侧：一批 = 一个审读员一个 fresh context 判得完的量，人只在成书后读一次，见 [ADR-0005](0005-full-autopilot-mode.md)）；**轴的名字会变**（同轴超 15 条要拆轴，边界还会吵）；**阅读次序会反复重排**（全书按自治成熟度阶梯排序）。所以：一条灵感一个文件、扁平放 `book/`；**编号是永久身份，次序是可改的编排，两者的真源分开住**。

## 布局

```
book/
  index.md                ← 次序的真源：一张全局有序表（文件名 / leading word / 主轴 / 次轴）+ 书级 front matter
  037-fog-of-war.md       ← 一条灵感 = 一个文件（编号 + leading word 的 kebab），**纯正文**，首行 H1 = 中文标题
  037-fog-of-war.card.md  ← 门槛卡 + `status`：兄弟文件，**永不导出、永不喂冷读**
  graveyard.md            ← 遗弃名单：烧掉的编号、曾用标题、弃因
notes/
  <axis>.md               ← 摘记池：一轴一文件，只追加，--- 分隔，无元数据
research/                 ← 研究票的落盘产物
docs/adr/
```

- **一条灵感一个文件，扁平不按轴建目录**：轴会改名、会拆，编进路径的维度迟早撒谎。轴是 `index.md` 里的列。**（被 #13 改）**原句是「轴是 front matter 里的字段、`index.md` 里的列」——稿件不再有 front matter，轴只剩 index 一处。
- **slug 取 leading word 的 kebab**（`037-fog-of-war.md`）：leading word 就是这条灵感的身份，它的真源是 `index.md` 那一行（kebab 会丢掉大小写与汉字，slug 只是指针）；**中文标题住稿件首行 H1**。**（被 #13 改）**原句的「中文标题住 front matter」见下条。
- **摘记池照抄 matt `writing-fragments` 的原生形态**：单文件、只追加、`---` 分隔、无 front matter、只有一个 H1 工作标题。`writing-shape` 规定成稿写进**另一个**文件——这里就是那个另一个文件，原始堆只读。

## 身份与编排

- **稿件文件是纯正文**（[#13](https://github.com/JoeWest9966/md/issues/13)）：没有 front matter。身份分三处、各只住一处——**编号**在文件名（`037-` 前缀，永久身份）、**标题**在稿件首行 H1、**`leading word` / `主轴` / `次轴`** 在 `book/index.md` 那一行。
- **`status`（`draft → reviewed → final`）住门槛卡文件 `book/<nnn>-<slug>.card.md`**：状态是过程事实，和卡同住「过程记录文件」。翻 `reviewed → final` 的是**书级冷读那一会话**，不是起草会话（[ADR-0005](0005-full-autopilot-mode.md)）。
  **（被 #13 改）**原句把身份与 `status` 一起放在稿件 front matter。身份的去处见上一条，`status` 的去处就是本条。
- **门槛卡搬出稿件**（[#13](https://github.com/JoeWest9966/md/issues/13)；原为「挂稿件 front matter」，见 [#5](https://github.com/JoeWest9966/md/issues/5) 与 `GLOSSARY.md`「门槛卡」）：它是**审读**的输入格式，不是书的内容，所以不跟正文住一个文件。住兄弟文件，**四栏**、一行一关：`两边在场`（事实）/ `增量价值` / `反直觉` / `何时别用`（举证）。原五栏里的 `leading word` 栏删掉——它是身份，已经在 index 行里住着（「一个事实只住一处」）。
- **谁填哪一半**：毕业（选料票）建卡并填 `两边在场` 与 `反直觉`（毕业审读判的就是前三关）；写作批填 `增量价值` 与 `何时别用`。审读员是只读的，逐栏复判写在批票的结论评论里，**不写进卡**。卡与稿件同生共死：条被砍，两个文件一起删（理由见下面「烧号」条）。
- **编号**在**毕业**时发放，一次发一个轴段，永久、不复用、不回收。轴不参与编号（不做 1xx–8xx 分段：拆轴并轴那天，编号会集体说假话）。
- **次序**与编号无关，住在 `book/index.md`。编号不动，编排随便重排。
- **状态只在文件里，次序只在 index 里**：一个事实只住一处。index 不重复 status。**（被 #13 改）**原句还有「也不重复 leading word」——现在反了：稿件没有 front matter，`leading word` 的唯一真源就是 index 那一行。
- 弃掉的编号**烧掉**，进 `book/graveyard.md`（编号、曾用标题、弃因），**稿件与它的卡一起删掉**，git 历史留着。卡不作幸存证据：终读只能烧不能捞（[ADR-0005](0005-full-autopilot-mode.md)），留卡等于暗示可以捞，把取严的配重从一页**遗弃名单**退化成逐条复核（[#13](https://github.com/JoeWest9966/md/issues/13)）。选料时少写两条就**留空**——留空诚实，复用撒谎：复用的号会让旧引用指向另一条灵感，而且看不出曾经有过那一条。

卡的形状（栏名固定，一行一关；版式照 #5 的「固定栏、一行一关」）：

```markdown
---
status: draft
---
# 037 战争迷雾 · 门槛卡
- **两边在场**: …
- **增量价值**: 单边做法 / 组合做法 / 差异点
- **反直觉**: 单边基线 / 预言失败
- **何时别用**: …
```

## 并发

- 一批 = 一张写作票 + 一个 agent 会话 + 一个分支，3–5 条灵感。批的大小由**审读质量**定（一个审读员在一个 fresh context 里判 3–5 条，判词还引得出原句；再大，判词退化成形容词）——「由人的阅读预算定」那条口径已被 [ADR-0005](0005-full-autopilot-mode.md) 废掉（人只读成书后那一次）。
- **并发口径：跨轴并行、轴内串行**——默认同时 2 批，**硬顶 4 批**（阶梯四级各一批），**硬规则是不许两批同轴**。同轴并行会让轴内重复检测失灵（两批都看不见对方），而号段本来就按轴排队。新上限防的是：同轴并行、同一台阶上两批半成品互相拉扯（轴间配平判不出来）、并发写作批的合并冲突。
- **谁写谁锁定**：这批要建哪些文件，选料时就在票里列全，别人不许碰。**写作批绝不碰 `book/index.md`**——那一行由选料票一次写好。于是并行批之间零共享文件。
- 默认**串行**：一批写完、审完、合完，再开下一批。要并行就给每批一个 worktree；同一个工作树里两个 agent 各切分支是灾难。

## 地图与票

- 一轴一张**选料票**，产出「这一轴是哪 12 条 + 轴内次序 + 号段 + index 行 + 每条的卡文件（前两栏）」。
- 动笔时按**批**开写作票。一个审读员一个 fresh context 判不完的批就是坏批——批太大，判词退化成形容词，等于把质量关拆了。
- **批级记录住在票里，不另开文件**：一批的**审读**总判与四个质量信号（零砍批 / 轴内重复 / 终读翻盘率 / 遗弃名单空转；**零砍批** 已由 #9 校准改判成 **零发现批**，见 [ADR-0005](0005-full-autopilot-mode.md) 第四条加注）写在该批那张票的结论评论里。「答案在评论里」这条与**决策票**同规。
- 不开 100 张「一灵感一票」：gh 2.23 没有 sub-issues，父子关系靠地图正文里手写的 task list；100 行手工账，且每关一张都要回去改地图。

## Considered Options

- **一轴一文件装 12 条灵感**（弃）：改一句 diff 一大片，两个 agent 同写必踩。
- **全书一个文件**（弃）：并发直接死，审读没法按条进行。
- **按轴分段编号（1xx–8xx）**（弃）：拆轴那天编号集体说假话，与「轴会变」直接冲突。
- **编号 = 阅读次序**（弃）：一次插队就是重命名 + 所有票和评论里的引用失准。
- **编号复用**（弃）：引用指向另一条灵感，且抹掉「曾经有过、后来弃了」这段事实。
- **用目录分组表达次序，或另开一份 `book/order.md`**（弃）：次序与轴的分组不是一回事——书按成熟度阶梯排、会跨轴；两个文件记两件事，不如一张表。
- **门槛卡留在稿件 front matter**（弃，[#13](https://github.com/JoeWest9966/md/issues/13)）：卡与正文同住一个文件，于是「**冷读**只喂正文」只能靠一次手工剥 `---`，而要剥的正是审读员要读的卡——剥不干净就是隔离自证。物理代价实测 30% / 34%（#9 校准），100 条都得手工维护这个比例。
- **只把卡挪成兄弟文件、身份仍留 front matter**（弃，[#13](https://github.com/JoeWest9966/md/issues/13)）：剥的动作没死，只是从三十行变六行；稿件仍然同时是「书文本」和「元数据」，冷读喂什么依旧靠纪律而不是靠文件形态。
- **卡拆进 `book/index.md` 逐条一行**（弃，[#13](https://github.com/JoeWest9966/md/issues/13)）：index 要短到能手工维护，卡是散文，塞进去等于把 index 变成第二份真源。

## Consequences

- 写一条灵感的顺序是：先毕业（选料票发号段 + 写好 index 行 + 建卡并填前两栏），再落地文件（写作批建稿件、补齐卡的后两栏）。
- `book/index.md` 由选料会话独占写入；写作批只新建自己名下的文件。
- 导出器（形态待定）从 `book/index.md` 头部取书级 front matter、从 index 的行与稿件首行 H1 取身份；**只导出 index 有序表里列到的条目文件**——`*.card.md` 与 `graveyard.md` 永不导出。两边都不许有第二份真源。**（被 #13 改）**原句：「从单篇 front matter 取身份」。
- **字数口径**（#10 转给第一张写作票的那笔账，这一半在此结清）：计数对象只剩一个——稿件文件（正文，含**行为示意**块）。「含不含门槛卡」这个问题随着卡搬走而消失。
- **没有生成器**（CLI 工具在范围外），index 是人肉维护的表——所以它必须短到能手工维护。这条反过来限制了哪些字段有资格进 index。
- 新增流程词进 `GLOSSARY.md` 时标 `档位: C（流程词，不进正文）`，免得被派生出书尾术语表。
