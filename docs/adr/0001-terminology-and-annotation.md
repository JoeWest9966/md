# 术语译名与注解策略

Status: accepted（决定于 [#6](https://github.com/JoeWest9966/md/issues/6)）

书的正文是中文，读者是已经在用 coding agent 的工程师。原语名（harness、commit、turn…）与 matt 侧的 coined 词（tracer bullet、fog of war…）正是他们要在代码、文档、对话里真正使用的词：译成中文就认不出、搜不到。全篇裸英文又会让中文句子碎掉。所以：**按词分档，档位决定它在正文里长什么样**；注解在出现处就地给一句边界，定义留给书尾术语表。

## 四档

| 档 | 判据 | 正文形态 | 例 |
|---|---|---|---|
| A 保留英文 | 运行时自造专名；译了会让两个不同原语看起来一样 | 英文原词，首次斜体 + 括号注解 | harness、commit、entry、turn/run、registry、codemode |
| B 中文为主 | 中文技术语境里已有唯一、不歧义的译法 | 中文译名，首次括注英文 | conversation→对话、task→任务、document→文档、tool→工具 |
| C 中文自造词 | 书自己的主语 | 中文，不括注 | 灵感、轴、门槛、骨架、地图、决策票 |
| D 保留英文的 coined 词 | matt 侧生造成语；译了就认不出 | 同 A | tracer bullet、fog of war、leading word、grounding |

判定规则：**这个词在中文技术语境里有没有唯一、不歧义的译法？有 → B；没有，或译了会抹掉边界 → A/D；书自己的概念 → C。**

**字面名不译**：枚举值与选项名（`pending`、`faulted`、`replay: "safe"`、`whenBusy`）、方法名（`submit()`、`commit()`、`fork()`）、`pi.*` kind 逐字保留英文，不占档位、不做术语注解，只在首次出现处给一句「它是哪一层的东西」。它们不是词汇，是 API 表面；读者要拿它们去 grep 源码和 issue。

逐词档位写在 `GLOSSARY.md` 的词条里（`**档位**` 一行），不在这份 ADR 里。

## 注解

- **形态**：行内全角括号，紧贴词后，一句 ≤ 25 字，只给边界那一句——注解的活是让读者不停下来，不是把定义搬进正文。
- **触发点**：**每章首次**，不是全书首次。章节会被单独转发，跳读者的第一个术语也得有注解。
- **排版**：首次斜体，之后直排。不引等宽字体（书不写代码）。

## 书尾术语表

由 `GLOSSARY.md` **派生**，读者向，只做精简：一条一句 ≤ 30 字，英文原词按 A–Z，中文自造词单独一小节。

- 收：A/D 档词、读者可能不熟的 B 档原语、C 档核心词。
- 不收：通用技术词（agent、prompt、token、context、LLM、API）、只在引文里出现的专有名词、`GLOSSARY.md` 的 `_Avoid_` 列表。

## 真源边界

`GLOSSARY.md` 管「写作时用哪个词、别用哪个」；书尾表管「读者不知道这个词时查什么」。前者是唯一真源，后者是它的子集视图，不加新信息。

## Considered Options

- **脚注 / 边注**（弃）：EPUB 流式排版放不住边注；脚注在三种出货形态里实现各异，且要求读者跳转。行内括号不打断理解。
- **全书首次注解**（弃）：跳读者拿到的第一个术语就是裸英文。
- **术语表单开一份 `book/terminology.md`**（弃）：两份维护必漂，而写稿时本来就逐词过 `GLOSSARY.md`。
- **全篇保留英文、不设档位**（弃）：正文会碎，且 conversation / task / document 这类词中文里本来就有干净译法。

## Consequences

- 新词进 `GLOSSARY.md` 时必须同时写档位；漏了档位，正文写法就没有依据。
- 书尾术语表是派生物：改了 `GLOSSARY.md` 就重新生成，不在书里手改。
- 100 词量级，手工同步可接受。
