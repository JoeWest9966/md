# 八轴：定名、边界、配额与阶梯

Status: accepted（决定于 [#4](https://github.com/JoeWest9966/md/issues/4)）

100 条灵感要分进八轴、按一条阶梯排序。轴的名字会进目录，边界会成为「这条归哪一轴」的唯一判据，配额决定一个轴立不立得住。三者不一起定，选料时每一条都要重吵一遍，而且每吵一次都可能换个答案。所以：**轴按工程问题划、按四级阶梯排；配额是靶心不是 KPI。**

## 决定

### 一、定名

| 轴 | 阶梯 |
|---|---|
| 记忆与延续 | L1 存续 |
| 委派与并发 | L2 运转 |
| 验证与信任 | L2 运转 |
| 上下文经济学 | L2 运转 |
| **共同语言** | L3 托付 |
| 计划与路线 | L3 托付 |
| 失败与恢复 | L4 放手 |
| 人类检查点与注意力 | L4 放手 |

只动了一个名字：**「领域语言建模」→「共同语言」**。「建模」是流程名不是工程问题名（与「轴」词条「取 engineering 问题而非技术特性」直接冲突），而且读者扫目录认不出这一轴管什么；matt 侧的第一杠杆原话就是 shared / ubiquitous language。其余七名照旧。**「人类检查点与注意力」保留「人类」**：删了它这一轴就退化成 agent 检查点，立意丢了。

### 二、边界：三条判据

1. **按工程问题划，不按原语划**。「用了 Document」不把一条灵感送进「记忆与延续」——问的是它解决哪类问题，不是它调了哪个原语。
2. **主轴 = 「天真做法为什么不够」那一段讲的问题**。骨架里本来就有那一节，所以主轴是**从稿子里读出来的**，不是作者自选的：审读判得动，作者也没法为了配平而改口。
3. **两边都沾时**：主轴给**反直觉点**所在的那一轴，次轴给**提供机制**的一方。

| 轴 | 归它 | 明确不归 |
|---|---|---|
| 记忆与延续 | 历史与状态怎么活过会话、崩溃、换人 | 存储选型；省 token（→上下文经济学） |
| 委派与并发 | 多 agent／多任务的编排、隔离、所有权、收束 | 单 agent 的做事顺序（→计划与路线） |
| 验证与信任 | 什么算证据、谁来判、判据何时必须存在 | 失败之后的收拾（→失败与恢复） |
| 上下文经济学 | token／往返／注意力的花销与替代（compaction 的代价、code mode、tool_search） | 正确性本身 |
| 共同语言 | 术语、命名、共享词汇当施工对象 | 写作技巧本身 |
| 计划与路线 | 做什么、什么顺序、边界画在哪（wayfinder、to-tickets、seam 先行） | 开工之后的执行细节 |
| 失败与恢复 | 失败之后：重试／幂等／放弃／沉淀成环境 | 失败之前怎么防（→验证与信任） |
| 人类检查点与注意力 | 人何时被拉进来、被拉进来时看到什么 | agent 之间的交接（→委派与并发） |

### 三、G7「环境即产品」并进「失败与恢复」

matt 侧 38 个动作聚成七组，其中 G7（retro / chief-of-staff / setup-\* / git-guardrails）的机制是「失败的正确出口是改环境，不是记性」，八轴里没有它的落点。裁决：**并进「失败与恢复」**——G7 处置的是已经发生过的失败，和重试／幂等／放弃是同一段旅程的最后一站；并进之后该轴边界写成「失败之后的一切：恢复语义 + 把失败沉淀成环境」。**不开第九轴**：八轴、副标题的「一百」、阶梯四级全挂在 8 这个数上，为一个分组动地基不值。

### 四、主轴必填，次轴按需

缺次轴时**门槛卡**里写一句为什么（如「本条机制只落在一轴」）。有次轴就必须在正文里真的找得到那一轴的机制，否则审读判凑数——强制的次轴会招来凑数，和「车轱辘话」是同一种病。

### 五、配额

- **靶心 12 / 硬顶 15 / 软底 8**。超 15 拆轴；某轴连 8 条都凑不出，说明它不是真问题类别 → 并进邻居，别硬凑。
- 事实先摆明：**12 × 8 = 96，当前假设本身就够不到副标题那个「一百」**。不足 96 时的处置顺序：**先拆超配轴 → 再合薄轴 → 最后才动副标题**。
- **100 是目标不是 KPI**；宁可改副标题也不灌水，裁的人是人（定轴定调是他的两件事之一），agent 只出证据与建议。

### 六、阶梯与轴内次序

八轴的先后是一条**自治阶梯**：每往上一级，机器能自己扛的多一分、人在场的时间少一分。现有顺序正好落成四级，**不重排**：

- **L1 存续**：机器活得过自己这次进程
- **L2 运转**：能同时干几件事、说得出干成没有、还付得起
- **L3 托付**：不用每次重新解释世界，也能被按计划追责
- **L4 放手**：翻车变成日常；人从「订阅」变成「事件」

轴内那 12 条**按前置依赖排**（grounding 序：一条灵感要落地的概念不能是后面某条才引入的），与「编号」无关（编号永久、次序可重排）。

## Considered Options

- **开第九轴「环境即产品」**（弃）：8 → 9 轴，配额、阶梯、副标题全要重算；为一个分组动地基。
- **G7 并进「计划与路线」**（弃）：G7 是失败的**出口**，不是事前的布局；并进计划轴会让「失败与恢复」只剩重试语义，太薄。
- **三级阶梯**（把 L2 与 L3 合成「托付」，弃）：委派／验证／上下文是「一次动作之内」的事，语言／计划是「一段旅程之内」的事，混一级读者失去爬升感。
- **强制次轴**（弃）：招凑数。
- **配额当 KPI，凑够 100**（弃）：与「宁缺毋滥」直接冲突，且 12×8 本来就只有 96。
- **轴内也按阶梯排**（弃）：阶梯是轴之间的性质；轴内要解决的是「读者读到这条时该懂什么」，那是 grounding 序。
- **保留「领域语言建模」**（弃）：与「轴取 engineering 问题」的判据冲突，且目录上不可读。

## Consequences

- **`GLOSSARY.md` 的「轴」词条要同步**：「每条灵感声明一个主轴与一个次轴」→「主轴必填、次轴按需」。**本 ADR 落地时未同步**：另一个会话正在并发写 `GLOSSARY.md`（写者互斥），改由后续会话补，或在 #6 落地后一并改。
- 每轴一张**选料票**（[ADR-0002](0002-file-layout-and-numbering.md) 已定形态），选料票按本 ADR 的边界表分轴；先做一张**各轴候选清单**票把候选摊开，再逐轴开选料票。
- 八个轴名进目录，四个台阶名可做部分标题的上位标签（留给导言票，属雾）。
- 选料票判「这归哪一轴」时只引本 ADR 的边界表，不再重新论证。
