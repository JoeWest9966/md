# 对抗性审读

纯文稿没有「跑一下」这种检验。**门槛卡**就是「跑一下」的替代品（见 [#5](https://github.com/JoeWest9966/md/issues/5)），**审读**的活是把它判假。

分工一句话：**门槛是判据，审读是拿判据去判假的动作；审读只证伪，不裁「这算不算灵感」——那是人的一票。**

## 单位与时机

- 单位是**批**（ADR-0002 的批：一张写作票 + 一个会话 + 一个分支，3–5 篇），不是篇。一批写完、审完、合完，再开下一批。
- 两次审读，对齐 #5 的分关判定：
  - **毕业审读**（起草前）：`两边在场` / `leading word` / `反直觉` 三栏。逐条毕业时就审——错判的代价是一条废稿。
  - **成稿审读**（成稿后）：`增量价值` / `何时别用` 两栏，加冷读轴。
- 触发：起草完成即自动起审读（AFK）。人只在收到「砍 / 上呈」短清单时出面，不逐篇读卡。

## 审读员：人格与隔离

三个 fresh-context、只读、替换 system prompt 的审读员**并行**，各持一个角度。pi-subagents 的 `reviewer` profile 就是这个形状（`systemPromptMode: replace`、`inheritSkills: false`、tools 只有 `read/grep/find/ls`）。

替换人格正文：

```
你是《哲学与运行时》的目标读者里最不宽容的那一个：你已经在用 coding agent，见过太多把
已知东西换皮成「洞见」的文章，随时准备把这一篇关掉。你的活是把它判假，不是把它夸好。
先给杀它的理由；给不出理由，才说通过。
```

- **喂**：正文 + 门槛卡 + `GLOSSARY.md` + 同轴已毕业条的 leading word 与三行差异点**索引**（不是全文）。
- **不喂**：起草会话记录、作者自述意图、其他审读员的报告。审读员之间互不可见，父会话合议。
- 理由：知道作者想说什么就会自动给他补台阶；「换皮」只有不懂意图才挑得出来。
- **引不出句子＝无法判定**：每栏判词必须引到正文的具体句子。引不出只能写「无法判定」，而「无法判定」按「差一关偏软」走补判，**不按砍走**——引不出句子是审读员没证据，不是稿子有罪。

## 三个角度

1. **增量价值**：对着卡片上「单边做法 / 组合做法 / 差异点」三行，问差异点是不是**读者可观察到的行为差别**（不同的轨迹、可见状态、失败表现）；形容词一律不通过。**换皮**（差异点退化成形容词，即车轱辘话）是本角度的第一号猎物。
2. **骨架与 ground**：骨架七槽齐不齐；正文有没有**没 ground** 的术语或概念（grounding 两种：前提 / 就地引入，见 ADR-0001 与 `GLOSSARY.md`）；两边是否都在场且各自不可替代（缺一边稿子就塌）。
3. **冷读复述**：见下。

顺带一句（每个审读员都答）：**这条和同轴已定的哪条是同一件事？** —— 只做索引级比较，不喂全文。

## 两轴，分开报，不互相抵消

- **轴一 门槛卡复判**（作者侧：这条值不值得进书）
- **轴二 冷读**（读者侧：读者接不接得住）

两轴分开报。一轴过、另一轴挂是常态（matt `code-review` 的两轴就是这个理由）；合并会掩盖。**冷读不是第六道门槛**（#5 已否掉第六关）。

### 轴一 · 门槛卡复判格式

一篇一份，逐栏一行：`栏名 | 判词（引原句） | 过 / 不过 / 无法判定`，末尾一行**总判：过 / 补 / 砍**。毕业审读只填前三栏，成稿审读只填后两栏。

### 轴二 · 冷读报告格式（≤300 字）

```
复述：<leading word 复述得出来吗；复述成了什么样>
边界：<说得出何时别用吗；说不出就写「说不出」>
裸术语：<哪句术语或概念没有 ground，引原句>
```

冷读由**另一个**无上下文、只读正文的 agent 做，它不看门槛卡、不看审读员报告。

## 出口表

| 总判 | 触发条件 | 处置 |
| --- | --- | --- |
| **过** | 五栏全过 | 起草 agent 翻 `status: reviewed` |
| **补** | 差一关偏软 / 无法判定 | 作者补举证或重写该栏；补判至多三次，第三次仍不过按「砍」或「退回」处理 |
| **砍** | 差异点写不出可观察行为差别（**唯一硬砍路径**） | 烧号进 `book/graveyard.md`，文件删掉，git 留史 |
| **退回** | 毕业审读三栏不过 | 退回 `notes/<axis>.md` 摘记池，不占编号 |
| **上呈** | 审读意见分裂 | 升级给人，投「算不算灵感」那一票 |

轮数是**补判轮，不是重审轮**：重写后只重审被改的栏与受影响的栏，不做全文复审——全文重审会把「改到过」变成磨洋工。

## 裁决权与 status 流转

```
draft --(审读总判「过」，起草 agent 自动翻)--> reviewed --(人合批)--> final
```

- **明显档审读员自裁，分裂档上呈人**（#5 已定）。审读员是只读的，翻不了 status；翻由起草 agent 按总判执行。
- **读而不判**：人合批时通读整批（批大小本来就按他的阅读预算定），但不逐条填判定，**只在被冒犯到时开口**；没开口＝默认过。这是 #5「只在 borderline 投票」与 ADR-0002「他一次读得完」的同一件事的两面，人的那两项职责没多出第三项。
- 人**能翻盘**审读员的「砍」，但翻盘必须写进 `book/graveyard.md` 旁的合批记录里——否则这条规则立刻变成救自己偏爱稿的后门。

## 这套机制自己的质检

| 信号 | 含义 |
| --- | --- |
| **翻盘率**（人开口推翻审读判定的比例） | 持续偏高 ＝ 审读员过严或误判 |
| **零砍批**（一整批一条没砍） | 连续出现 ＝ 审读员在点赞；宁缺毋滥的机制不可能批批全过 |

两个信号落在合批记录里。**#9（两篇样章）是这套机制的第一次试跑**：样章本来就要验证骨架，顺带验证审读员挑不挑得出真问题——两篇样章审读下来一条问题都没挑出来，就是机制没用，回来改这份规程。
