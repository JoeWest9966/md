# 迟到者不补播

让人看进度和让人做决定，是两件事。前者的直觉做法——把错过的一切补给他——在运行时里根本不存在。

**场景**。一个跑了两小时的活儿：五步做完三步，第四步卡在需要人点头的地方。你前 90 分钟在开会，回来打开界面。你看到的是：三个已完成的任务、一个在等、一句「要删掉这 400 张孤儿订单吗」。没有回放，没有「这三步是怎么走到这里的」。要理解现在在哪，你不需要看两小时日志。

**天真做法为什么不够**。单边做法是 *push right*（把人被问到的时机尽量往后推，只问一次，且材料齐备）。它是好纪律，但它要一份保证才成立：**你晚到的时候，当前状态就是全部**。常见的会话流、事件流给不了这份保证——重连的客户端要么丢帧，要么给你补播一大段，而补播回来的已经是过去的事实。人一旦要自己从流里重建「现在在哪」，检查点就从一次决定退化成一次考古。

**组合机制**。运行时侧有两条事实正好是那份保证。一是 *commit*（一次原子写，要么全存要么全不存）之后状态才可见：所以「当前视图」（view：会话此刻的只读状态）不是对进度流的近似，它就是全部事实。二是 *watch*（订阅某个会话的变更流）对迟到的客户端**不补播**：它从当前视图开始，什么都不重放，最多缓冲 100 帧未交付的更新——而那个缓冲是给慢消费者的，不是给人的历史。

于是人的检查点有了形状：**当前视图 + 一句话的待决问题**。而检查点的内容由任务（task）自己的状态机给齐了——完成、等待、待决都在视图里，不需要旁白，也不需要人去读日志。push right 因此可以推得很远：人晚来多久，都不影响他看到的东西的完整性。

**行为示意**。

```
第 0 分钟   派活：清理孤儿订单（5 步）
第 12 分钟  前三步完成，状态落盘
第 90 分钟  你在开会；第四步做完，第五步要人点头
第 95 分钟  你打开界面
            视图：3 完成 / 1 等待 / 1 待决
            一句：「要删这 400 张孤儿订单吗？」
            没有回放，也没有「我漏看了什么」这回事
```

**何时不适用**。要**证明**发生过什么的时候。视图不是账本：它没有历史，重连不补播，跨会话也不汇总花费。事故复盘、计费、合规这类要求，事实必须写成不可变的 *entry*（记录：一条不可改写的条目，历史只能追加）。拿界面当审计，等于让「后来的人看到的」冒充「当时发生过的」。此时单边的「把一切都记下来给人看」是对的，而且是唯一对的。

**回扣**。迟到者不补播：因为不补播，检查点才可以是当前状态而不是一份进度；反过来，需要历史的地方，历史必须是被写下来的，不是被看到的。
