## 切法：本票的产出

票面要的是**切法**：哪些概念当**前提**、哪些**前言 ground 一次**、哪些留给**章节就地注解**。切法卡里的三张清单就是答案，但真正承重的是**判据**——前三轮它在稿子里没成文，所以三轮里每一轮的「抢了章节的活」都判在不同的地方。

**判据（第四轮钉死，写进切法卡）**：一条概念进「前言 ground」，要**同时**满足

1. **正文从头到尾拿它当闸用**——依赖计数是佐证，不是判据；
2. **它是「关系」而不是「词条」**——GLOSSARY 里一句定义给不出它。

只满足 ① 的（典型：`Run` 的「成败边界只有三种」）走章节。三轮审读三次提议把**文档**、**扩展**降为章节，唯一的理由是计数只有 4；按判据 ② 保留：「寿命挂在归属上」「代码在进程里、名字在存储里」是关系，一句括注确实给不出。**这不是取宽**——三次提议都记在案，判据写清了才留。

**依赖计数**（口径＝该词出现在 8 个轴文件里多少个的摘记中，99 条候选）：

| 进前言 ground | 计数 | 留章节 | 计数 |
| --- | --- | --- | --- |
| 会话（Session/Harness） | 7 | submission | 3 |
| 任务（Task） | 6 | run | 3 |
| 视图（view/watch） | 6 | turn | **1** |
| entry | 5 | run 的「成败边界三种」 | **0** |
| commit | 4 | checkpoint | 0 |
| 文档（Document） | 4 | | |
| 扩展 / Registry | 4 | | |
| 外部效果 | 4 | | |

counts 是**佐证**：`Turn` 是 1、`Run` 的成败边界是 **0**，这两个数字一出来，一稿里那段「三种成功结束 / 最贵的一类误判」就直接降级到章节了——审读员的主张与计数同向，不需要谁让步。反过来 `外部效果`（4）被三轮审读提议降级而本票保留：判据 ② 说得清它为什么在（「效果有没有发生是你的事」是一条关系，不是词条）。**这一处是驱动者的过判，理由在卡里，不在判词里。**

**入场的八个概念**：Harness/会话 · entry · commit · conversation · 任务 · 文档 · 扩展/Registry · view/watch。
**四条信念**：反馈速率是速度上限 / 共同语言是第一杠杆（正文写「共同的词是回报最高的一步」，避开 `杠杆` 的深模块义）/ 组合优先于堆积 / 人的注意力是稀缺资源。

## 两个方向的失败，判在哪

票面要的是把两个方向的失败在这一篇上试出来。四个方向都判到了：

**① 挡在门外**（前提里混进单边专有 → 单边读者进不来）

- 一稿：切法卡把 `transcript` 列进通用词，正文却拿它当 durable 的「transcript 作用域」用 → **改**：正文不再用 `transcript`，Conversation 的括注改写成「一段工作自己的范围」。
- 二稿：审读员指出 `提交` / `事务` / `入口` / `接口` / `边界` 全是 `GLOSSARY.md` 明令避开（`_Avoid_`）的词，正文拿它们当锚 → **改**：全文改写为 `已 commit` / 「任何一次 commit 里」/「对外的第一层」/「调外面的服务」/「各自管到哪」。
- 三轮：`杠杆` 是 B 档承重词（深模块那一族），拿来当「第一杠杆」是义漂 → **改**：改写为「共同的词是回报最高的一步」。
- 三轮：`push right` 的括注写「把检查点向右推」，而 `checkpoint` 在 durable 侧是 task 的落点，两义撞一个词 → **改**：写「把人被问到的时机再往后推」，并在 `GLOSSARY.md` 立一条 Flagged ambiguity。

**② 抢了章节的活**（前言把本该章节一句括注的东西提前烧掉）

- 三轮里审读员分别点了 `外部效果` / `文档` / `扩展` / `run 的成功边界`。前三个按第 4 节那条判据保留（判据成文之前它们看起来都是「浪费」）；**`run 的成功边界` 降级到章节**——计数是 0，而且它原本是一段带「最贵的一类误判」的成篇料。
- 一稿把 `接缝`（seam）写成了一个技术定义，而它被列入「章节不碰」→ **改**：定义删掉（换成「先想清楚改动从哪一处进去」）；同时全书题眼的「两个世界的接缝」改成「两个世界重叠的那一处」，`接缝` 整词退出前言。
- `扩展` 的分界线原来拖了一句「卸载不是把代码删掉，改名也不是纯重构」——那是「共同语言」轴第一号摘记的正文料 → **改**：删掉，前言只留分界线本身。

**③ 漏网**（当已知用、三张清单都没收）

- `八轴`（一稿两轮、四个冷读里有三个挑它）→ **改**：首次出现就地给边界，「全书目录就是这八节」。
- `前沿`（B 档，前言用了自己说好不碰的词）→ **改**：换成「手头所有待决的事」，整词退出前言。
- `红`（GLOSSARY 的 D1 词，被放进「前提」）→ **改**：从前提摘出，正文首现括注「红＝测试挂」，并列入「前言的例外」。
- `单边做法` / `状态机` / `matt skills` / `pi` / `skill` / `原语`：`单边做法` 首现补边界、`skill` 与 `pi` 各补半句；`状态机` 与 `原语` 判**通用技术词**，免注（这一条与审读员意见相反，理由记在案：它们两边读者都带着，而且正文紧接着就把 durable 特有的那一半说明白了）。

**④ 卡与正文打架**

14 个 run 里这一栏命中最多，全部是记账问题而不是稿子问题：正文给了、卡没列（Harness / Document / Registry / checkpoint / hook），或卡说没给、正文给了（`会话 ≠ Conversation`、`run 成功边界`、`接缝`）。**改**：卡的三张清单逐条对到正文，多出来的记进「前言的例外」。

## 探针：已知病灶复现

照 [#9](https://github.com/JoeWest9966/md/issues/9) 的做法，本票也留了一个**已知答案**的探针——这是这套机制唯一能被证伪的地方。做法：拿一稿的正文不动，只**篡改切法卡**，把两条真正的前言 ground 项偷偷搬进「前提（读者走进来就该懂）」：

- 「会话和 conversation 是两个词，各管各的」
- 「一次 run 什么时候算成功结束」

这两条正好是切法卡自己写的失败红线（「把 durable 专有的东西当常识」），而正文第四节、第七节明明给了它们——所以病灶是**可判定的**：任何审得动的审读员都该指出「卡说前言不给，正文却给满」。

**结果：两处全部复现。** `probe-P` 逐条写出「卡把它列进『读者走进来就该懂、前言不给』，等于把正文料当常识，正好命中卡自己的失败红线」，并把 4a / 4b 两条「卡与正文打架」单独列了出来。探针跑的是**同一个 prompt、同一个模型**，材料只差那一张被篡改的卡。

**探针自己的方法缺陷**（记在案）：给 `probe-P` 的材料目录忘了放 `GLOSSARY.md`，它开场就判「`GLOSSARY.md` ENOENT，凡依赖该宪法的判断一律按无法判定」。切法判断不依赖宪法，所以结论有效；档位判断这一路是空的。同一批的 `reviewer-A` / `reviewer-B` 材料齐全。

## 总判：**补**，冻结

- 每一轮的三个角度都判「切法需修 / 补」，**没有一次判「砍」或「退回」**。按出口表，要砍的两条路（差异点退化成形容词、成稿审读逐栏分裂取严）在前言这种文体上都不成立：前言没有「差异点」那一栏。所以能出现的只有「过」与「补」。
- **补三轮，第三轮仍判补**——这与 [#9](https://github.com/JoeWest9966/md/issues/9) 的结论同形（样章也冻在「补」）。要诚实说清楚**为什么不是「过」**：第四轮的四条判词里，「Commit / 任务两处标题先于首次注解」当场就改了；剩下的不是改不动，是**每轮都会新长出同田的下一茬**——判词越改越细（第三、四轮已经细到「`_Avoid_` 词出现在词条自己的定义里」），而实质结论（八个 ground 项、四条信念、三张清单）三轮没有被任何一次判假。
- **本票是 prototype**：它的产物是**证据**不是书稿，`/proto` 永不导出（[ADR-0002](../docs/adr/0002-file-layout-and-numbering.md)）。冻结的含义与 #9 一样——**不再磨**，判据已经落进切法卡并转给下一张票。
- 一稿 → 四稿的**净变化**：正文 2905 → 2947 字（汉字+拉丁词），删掉一整段（`run` 的成败边界）、新增三段（判据、头部字样、宪法缺口记账），二十余处措辞按 `_Avoid_` 表重写。

## 写在账单上（本票考不到的）

1. **计数口径**。`#9` 指出 400–900 字那条口径没成文，本票第一次把它钉死：**字数 = 汉字数 + 拉丁词数（不计标点与空白）**，并在 front matter 里同时报「不计空格字符」的读数（2947 / 4015，差 36%）。口径要交给**第一张写作票**复用，否则每批都会有两套字数。
2. **前言在整本书里的位置**。这篇是独立审的；它和 100 篇的关系（读者是不是真能拿着它进正文、部分导言会不会和它重复）只有**书级冷读**看得见。单位是整本，本票给不出。
3. **「八个概念」这个数**。它是票面给的，本票照办，但依赖计数说明真正被 100 篇依赖的只有 4–5 个（会话 / 任务 / 视图 / entry / commit）；另外三个（文档 / 扩展 / 外部效果）是靠判据 ② 的「关系而非词条」进来的。**如果整本书下来发现前言该薄到 5 个概念，改的是这个数，不是判据。**
4. **冷读的读数不稳**：同一批材料，C5 判「接得住」而 C6 判「杀」（它要一条正文里可独立检验的轨迹——前言按定义不给）。这不是谁错了，是 `#9` 已经记下的那条：**冷读是一次抽样，不单独定生死**。这次抽样里它给出的稳定信号只有一个——`八轴`，前后四个冷读里有三个挑它，改完第三个就没再挑。

## 证据：14 个 run 的原始报告全文

以下报告未经编辑，按 run 名逐个列出（run 的隔离材料与提示词见本记录的「跑了什么」一节）。

### `reviewer-A`

角度：**切法**。只读 `preface-two-worlds.md` 与 `GLOSSARY.md`。

## 一、挡在门外（「前提」清单逐条）

**前提条 1「已经在用 coding agent 干活：读得懂 diff 与工具调用，知道上下文有窗口、会被截断」——过关（无法判为某一侧专有）。**
它摆明是全书的读者地板，不是方法侧或运行时侧的独有常识；没有据此读不通的正文句子。无法判定为漏洞。

**前提条 2「通用技术词不注也不给：agent / prompt / token / context / LLM / API / transcript」——不过（「transcript」是运行时侧专有）。**
卡把 `transcript` 归进「通用技术词」，正文却按 durable 的专有意义用它：

> *Conversation*（transcript 作用域）是「这段工作」的单位：它有自己的收件箱、用量、配置。

> 文档（*Document*）是放在 transcript 旁边的一小块类型化 JSON 状态

「transcript 作用域」「放在 transcript 旁边」都是 durable 的存储语义；方法侧读者手里最多有个「聊天实录」的日常义，没有 durable 的 transcript。卡自己承诺「单边读者的入场券：只懂方法论或只懂运行时其一即可入场」，这一条把方法侧单边读者关在门外。
补法：把 `transcript` 从通用词清单摘出，并入「前言 ground 一次」或首现括注半句。

**前提条 3「与本题无关的工程素养：git、测试、命令行」——过关。**
三个词都是工程地板，不限任一侧；但「测试」并不覆盖后文裸用「红」当测试失败的负载，见「漏网 3」。

## 二、抢了章节的活（「前言 ground 一次」条目）

**ground 条 3「外部效果不在事务里：intent → effect → outcome 这条缝」——一句括注可解决，且不构成全篇依赖。**
正文给它的建面：

> 由此推出一条容易被忽略的缝：**外部效果（发邮件、调第三方接口）永远不在事务里。**

这句话本身就是一句；只在正文处理「发邮件 / 调第三方接口」的章才真正被用。前言其它七点没有哪一处靠它才能读通。列入 ground，是把一节正文的料提前烧掉。
补法：移到章节就地注解，首次触「事务 vs 外部效果」处一句括注。

**ground 条 6「run 的成功边界只有三种，「没答上来」不等于「答完了」」——正文把它写成一个章节级论点，而非闸。**
卡标它「正文全篇靠它，逐章注解给不出」，但正文收尾处是：

> 把「没答上来」读成「答完了，只是没内容」，是所有自动化里最贵的一类误判。

「最贵的一类误判」是一条有「何时别用」面相的成篇料；枚举本身（答成 / 终止 / 交接）一句括注即给得出，前言其它段落也未依赖它。卡未提供任何一句正文证明「全篇靠它」。
补法：把枚举下放章节首现括注；「最贵误判」单独立章，不在序里 ground。

## 三、漏网（正文当已知用、不在「前提」也不在「前言 ground」）

**1. 「八轴」**
> 动作数量受控，可变的是组合方式；八轴乘三十八个动作的组合空间，就是这本书住的地方。

「八轴」是本书一级分类（GLOSSARY「轴」），序里第一次出现即裸用，没定义、也不在任何清单。单边读者无法从这句知道「轴」指什么。
补法：首现括注「轴＝灵感的一级分类，全书八轴」，或干脆删「八轴乘」。

- push right：>「这是 push right（把人被问到的时机再往后推）」——12 字，边界。唯一在正文出现的 D2 词，落位正确。

**不过**：

1. *Commit* 的首次出现无注。「**三、可见性等于已 *commit*。**」先于注解一句出现，注解在下一句「*Commit*（一次原子写：要么全成，要么全不成）能把好几样写入打包成一次。」——A 档词的首次出现比注解早一个句位。另外该注解前半「一次原子写」就是 GLOSSARY 原定义，后半「要么全成，要么全不成」才补了边界，属轻度抄定义，不致命。
2. *Submission / Turn / Run* 在正文出现但无注：>「剩下的名字——*Submission*、*Turn*、*Run*、工具、代码模式、环境、图片——各章用到的第一次会给一句注解，不在这里铺开。」按切法卡「章节就地注解」放行，不算缺口，但事实是正文里三个 A 档词裸出现，读者此处只能信后文的承诺。

## 2. B 档形态（首次括注英文）

- 会话 ✅：>「它打开的那个东西叫**会话（*Session*）**」
- 写入线 ✅：>「会话里只有一条写入线（mutation line）」
- 扩展 ✅：>「扩展（*Extension*）是一个命名束：一批工具……」
- 文档 ✅（durable 义）：>「文档（*Document*）是跟 *Entry* 在同一次写入里原子地改的一小块类型化 JSON 状态。」

**两处不干净**：

1. 任务：首次出现是标题 >「**五、任务是唯一有重量的东西。**」——无英文括注；「任务（*Task*）是……」晚一句才给括注。B 档首次出现不合格。
2. 文档的同形词先出现：>「两个世界都有自己的几千页文档」这里的「文档」是泛义 documentation、无注；B 档「文档（*Document*）」在第二处才注，且没标记这前后是两个义项。冷读者可能把「几千页文档」误当 durable Document。

## 3. 假 ground

正文逐项过了 `_Avoid_` 清单，**未发现**用 `_Avoid_` 词去解释另一个词。两点需要说明：

- >「模糊词给一个规范词，落地就写进文件。」「文件」是 Document 的 `_Avoid_`，但这里指方法论里真实写入文件，不是解释 Document，不计假 ground。
- 「宿主」在正文里没有出现，Harness 的释义干净。

**但 GLOSSARY 自身有两处假 ground，且其中一处 front matter 说已修而实际没修净：**

> 「**写入线**（mutation line）：会话里那条唯一的写入通道；所有写入排队从它过去，**提交过的才可见**这条保证就是从它来的。一条写入线 = 全局串行写入，所以**事务必须短**。」

「提交」是 Commit 与 Submission 共同列出的 `_Avoid_`；「事务」就是 Commit 的 `_Avoid_` 条目「transaction」。这一句在用 Commit 明令禁止的两个词去解释写入线的保证——不算 ground。

> 「- **Session** 是内核对象，**Harness** 是打开它的**宿主** API——不是同义词」

「宿主」是 Harness 自己的 `_Avoid_`。front matter 声称 >「Harness 的定义自己用了它的 `_Avoid_` 词『宿主』，一并改掉」——定义条目（Harness 词条正文）确实改了，但 Relationships 这行还是原文，改正没有落地到全部文件。

## 4. 缺口与越界

**越界：无。** smart zone / compaction / wayfinder / frontier / 战争迷雾 / 曳光弹 / 接缝 / checkpoint / codemode / tool-search / env / images 都没在正文被解释；Submission/Turn/Run 只点名不解释。通用技术词（agent、token、context）与字面名（*faulted*（失败态））未被误判成缺口。

**正文缺口：** 除第 1、2 条标出的「Commit / 任务 标题首现无注」外，没有该注而未注的概念。

**ground 的宪法缺口（不是正文注的缺口，但是真缺口）：**

- >「*view* 是这段工作此刻的只读状态，*watch* 订阅它的变更。」
  view / watch 在正文以英文术语入场并给了内联注，但 GLOSSARY 没有这两个词条。front matter 的「顺手指出的宪法缺口（已就地修）」只补了「写入线」与「push right」，漏了它们在正文同样以术语姿态出现的 view / watch。
- >「**外部效果（发邮件、调外面的服务）永远不在任何一次 commit 里。**」
  「外部效果」进了前言 ground 清单，正文也给了例注，但 GLOSSARY 无词条。

**同形异义，不判越界，仅记：** 正文标题与比喻 >「它要一张地图，且只要一张：不解释每一个地名」把「地图」当文学意象用，与 GLOSSARY「地图」（wayfinder issue，C 档流程词）同形；宪法没给这个文学义留位置。

## 总判

**补。**

不砍：正文 ground 的边界质量整体够硬，A/B 档注解基本逐条落地，没有假 ground，也没有前言抢章节主题。不能过：Commit、任务两处「标题先于首次注解」的落位违规，和 GLOSSARY 自身残留的「提交 / 事务 / 宿主」假 ground（其中「宿主」还是 front matter 声称已修未净）、以及 view / watch / 外部效果 的宪法缺口，都是要补的账。

### `coldread-C7`

1. **复述**：这篇主张 coding agent 的天花板「在两个世界重叠的那一处」——方法论单用只是纪律，运行时单用只是实现细节；所以书的一百篇「每篇取一条方法论的动作，配一到两条运行时的原语」，展示单边做法与组合做法的差别。

2. **边界**：能说得出。它声明「不解释每一个地名，只让读者看清两个世界各自长什么样、各自管到哪」；原语细则「属于 durable 自己的文档，这本书不复述」；一百篇「不分先后，但排成一条坡」。

3. **手里有什么**：读后有粗略形状：Session 是单写入线且不重试、Entry 不可变、可见性等于已 commit、Task 是留进展的状态机、Extension 名字在存储里、view 是全部事实、四条信念。**只听到名字**：*Submission*、*Turn*、*Run*、工具、代码模式、环境、图片、「八轴」、三十八个 skill 未列名。**从来没出现**：任一原语的完整细则、任何一条具体组合做法、调优参数、八轴具体是哪八个问题。所以读完只有地图和问题本身，没有正文本领。

4. **裸术语**：「八轴（本书的八个工程问题，全书目录就是这八节）乘三十八个动作的组合空间，就是这本书住的地方」——「八轴」是什么没解释；「matt skills」「pi」也只有标签。
