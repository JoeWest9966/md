# 效果在写入线之外

「提交了」是 commit（一次原子写）完成的意思，不是事情做成的意思。这两个说法在中文里只差一个字。

场景：agent 被要求给客户发一封确认邮件。它调用发信工具，拿到成功响应，把「已发信」写进 transcript（会话的全部记录）并 commit。就在这几步之间，进程被杀，重开。

单边读者的做法是真实的：tdd 与 implement（matt 的两个 skill：先红后绿的小步做，一票做完再交付）把 commit 当里程碑——测试绿、提交、任务划掉，世界就前进了。这对代码成立，因为代码本身就住在存储里。对任何「出门做的事」不成立：邮件不在你的存储里。而这条边界不是可选的边角，是所有对外动作的正中央。

durable（pi 的耐用运行时）给它起了名字：**外部效果**（external effect）——任何不在一次 commit 里的后果，发一封邮件、调一个外面的服务、写一个文件。它永不进 commit。为什么：commit 是原子的、串行的、可回放的；一个真把邮件发出去的动作不是。硬塞进事务只有两种烂结果——先记录后发，崩溃留下一条没发生过的事实；先发后记录，崩溃留下一次没记上账的发生。

durable 的答案是三明治，把效果夹在三段之间：写下 intent（意图，一条 *entry*——transcript 里一条不可变的记录）、出去做、写回 outcome（结果，同样是一条 entry）。commit（一次原子写）只管记录，不管发生。于是重开时的问题被收窄成一个具体的问句：「intent 有，outcome 有没有？」——而这件事得你自己去问外面的世界。

行为示意——同一封邮件，两种写法：

- 单边：发信 → 成功 → 写「已发」→ commit。崩溃点落在「成功」与 commit 之间：重开看不到任何记录，重试，客户收到两封。
- 组合：写 intent → 发信 → 写 outcome。崩溃点落在发信与 outcome 之间：重开看到 intent 没有 outcome，知道必须去查（或拿一个幂等键重发）。崩溃点落在两者之外：安全重试。

何时别用：三明治不替你解决那条缝，它只告诉你缝在哪。所以效果必须**可查**——要拿外面服务给的 id 或幂等键，否则 intent 也只是个死信；效果是不可逆的一次性动作（转账、发货）而外面又不提供查询方式，这个顺序救不了你，能救你的只有那个服务的幂等键，durable 没有魔法。反过来，效果本身便宜、可丢、代价可忽略（打一条本地指标、写一份下次会被覆盖的缓存），别为它建三明治——要在 commit 里留下那次调用的结果就够了。

记录和发生是两件事；the effect is outside the line，那条线不是画错了地方，是它本来就不在这条写入线里。
