# 共同语言 · 候选清单（wayfinder #11）

读法同 [`notes/记忆与延续.md`](<记忆与延续.md>)：一条一个摘记，六栏照 [#11](https://github.com/JoeWest9966/md/issues/11)；主轴恒为本轴，次轴按需，缺次轴时写一句为什么。

---

**01 · 名字是一份持久化协议**

- 一句话角度：conversation 里只存扩展的**名字**，kind 与可见路径也是持久化协议——改名的正确动作是显式拷贝退役
- 主轴：共同语言
- 次轴：记忆与延续（协议落在存储里）
- 候选 leading word：the name is a protocol
- 反直觉点在哪：以为改个名字是纯重构；实际它动摇的是已存数据的地基——而且 Session **不检测**两个 token 撞同一个 kind，改名与撞名都没有报错这一层
- 单边做法是谁：matt 的 domain-modeling（「冲突词立即叫停、模糊词给规范词」，靠当场的人把名字敲定）

---

**02 · 阻塞有名字**

- 一句话角度：`missing_task` / `task_too_old` / `migration_failed` 是被持久写下的理由，不是一个异常
- 主轴：共同语言
- 次轴：失败与恢复（挂着等装上的那段时间）
- 候选 leading word：named blockage
- 反直觉点在哪：以为「卡住了」是一种临时观察；实际它被名词化成状态的一部分，谁都能读出「为什么卡」——无法判定这件事先被命名，才可能被等
- 单边做法是谁：matt 的 triage（五个状态角色标签，把状态机名词化在同一批词上）

---

**03 · 词汇长出牙齿**

- 一句话角度：retro 的产出可以直接是一条 `beforeTool` hook 或 registry 规则——术语第一次有了执行器
- 主轴：共同语言
- 次轴：失败与恢复（G7 的机制落在那一轴：改环境而不是改记性）
- 候选 leading word：a glossary that bites
- 反直觉点在哪：以为「统一词汇」的收益在沟通；实际它最大的收益是能让同一个词在运行时里被强制执行——写进标准的词只能靠 reviewer 记着，装进 hook 的词每次都会拦
- 单边做法是谁：matt 的 retro（机械违规 → 确定性检查，判断类 → coding standards；标准仍由人执行）

---

**04 · 没有一个词指代整体**

- 一句话角度：文档 / 会话 / 任务图三个观察粒度之间没有统一总线，「session 级 watch」名不副实
- 主轴：共同语言
- 次轴：记忆与延续（三个粒度各自的历史）
- 候选 leading word：no name for the whole
- 反直觉点在哪：以为「整个 harness 的一条流」是缺一个 API；实际缺的是**这个词本身**——whole-session DOM 被列为 non-goal，于是没有名字的东西也没有接口
- 单边做法是谁：matt 的「看着它跑」（一个屏幕、一份 transcript，整体性由人对屏幕的直觉提供）

---

**05 · 接口就是一份清单**

- 一句话角度：codebase-design 的 interface 是「签名 + 不变量 + 顺序约束 + 错误模式 + 必填配置 + 性能特征」，durable 的 spec 逐条有物
- 主轴：共同语言
- 次轴：验证与信任（清单是判据）
- 候选 leading word：the interface is a checklist
- 反直觉点在哪：以为接口就是类型签名；实际把使用者必须知道的一切写成清单之后，「我该读哪一份文档」这个问题就消失了——接口的定义本身就是导航
- 单边做法是谁：matt 的 SKILL.md（散文纪律：must / never / always / done when，读者自己提炼）

---

**06 · 为了能 grep 而不译**

- 一句话角度：枚举值、方法名、`pi.*` kind 逐字保留英文——因为读者要拿它们去源码里搜
- 主轴：共同语言
- 次轴：—（机制只落在本轴：字面名是接口的一部分）
- 候选 leading word：grep-ability
- 反直觉点在哪：以为保留英文是「怕译丢意思」；实际理由是**可检索性**——译了之后读者搜不到，这个词就失效了，档位问题被降级成一个搜索问题
- 单边做法是谁：matt 侧中英混排的自然习惯（词按意思记，不按拼写查）

---

**07 · 措辞决定会不会被取**

- 一句话角度：一条指针的价值在**措辞**，不在它指向的东西——front-load 那个 leading word 才是它干活的地方
- 主轴：共同语言
- 次轴：上下文经济学（取不取决定花不花上下文）
- 候选 leading word：the wording is the trigger
- 反直觉点在哪：以为指针写清楚目标就够了（路径 + 一句说明）；实际触发是措辞干的活，写对了才会被取，写全了反而只是缓存
- 单边做法是谁：matt 的 `writing-for-agents`（同一条，但它只是写作技巧；durable 侧有 description→载入的机制做对照）

---

**08 · 歧义要有一节**

- 一句话角度：一个词两义并存时，正确动作是写进 Flagged ambiguities，而不是悄悄选一个
- 主轴：共同语言
- 次轴：记忆与延续（同一 token 在不同 scope 里各有生死规则）
- 候选 leading word：ambiguity gets a section
- 反直觉点在哪：以为歧义是靠「用得准」消灭的；实际它是被**记录**下来的——一个词两义一旦并存，沉默地选一个会让另一半读者永远读错
- 单边做法是谁：matt 的 GLOSSARY.md 三段式（Language / Relationships / Flagged ambiguities；这个词原本就有家）

---

**09 · 一个词，两处语义**

- 一句话角度：agent-event 的 snapshot 把退休文档读作初始值，`documentState` 看到 `null`——两处语义不同，别混用
- 主轴：共同语言
- 次轴：验证与信任（拿错那份做判据）
- 候选 leading word：same word, two meanings
- 反直觉点在哪：以为「同一个文档」在两个观察者眼里是同一件事；实际两处的语义边界不同，而这是个很容易被当成 bug 去「修好」的差别
- 单边做法是谁：matt 的 wait-what（用对方的词汇重讲一遍，而不是解释自己的）

---

**10 · 重复是一种腐烂**

- 一句话角度：同一含义两处写下来，就是下一次改动会漏掉一处的预约
- 主轴：共同语言
- 次轴：记忆与延续（唯一真源与派生物的关系）
- 候选 leading word：duplication is rot
- 反直觉点在哪：以为多说一遍更保险；实际 duplication / sediment / sprawl 是三种失效模式，其中 sediment 最阴——过期的那层留着，读者会先读到它
- 单边做法是谁：matt 的 `writing-for-agents` pruning 三失效模式（写在提示词规范里，靠人遵守）

---

**11 · 提示词是代码，不是散文**

- 一句话角度：system prompt 由 section 依序渲染、变更以 entry 存进 transcript——它是装配出来的产物
- 主轴：共同语言
- 次轴：记忆与延续（渲染与变更都留痕）
- 候选 leading word：the prompt is code
- 反直觉点在哪：以为系统提示是写给人看的一段说明；实际它有装配顺序、有缓存失效、有版本留痕——按散文改它，就会按散文出事故
- 单边做法是谁：matt 的 AGENTS.md / SKILL.md（一遍写好、整份读进去，靠写作质量保证）

---

**12 · 单向派生**

- 一句话角度：书尾术语表由 `GLOSSARY.md` 单向派生，不另立第二份真源
- 主轴：共同语言
- 次轴：记忆与延续（真源与副本的关系）
- 候选 leading word：one-way derivation
- 反直觉点在哪：以为「给读者看的版本」应该独立优化；实际一旦允许双向编辑，两份就开始各自漂移——派生方向是必须写死的第一件事
- 单边做法是谁：matt 的两份词汇（本仓 GLOSSARY.md 与各 skill 正文里的词汇用法，靠人保持不打架）
